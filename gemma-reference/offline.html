What it is

One-device AI, zero cloud

Google AI Edge Gallery is Google's open-source showcase app for running generative models entirely on-device through the LiteRT / MediaPipe runtime. Every inference — text, image, audio — happens on your own silicon. Nothing is uploaded, so it keeps working in airplane mode and your prompts stay yours.

What it's for: a private, offline sandbox to chat, read images, transcribe audio, run agentic skills, and benchmark open models — and to import your own from Hugging Face when the defaults aren't enough.

📌 Source of truth

Everything here is tuned for daily reference on an iPhone 17. Feature set and repo details from github.com/google-ai-edge/gallery and its wiki. Config numbers below are sensible starting points — nudge them to taste.

iPhone specifics

Mobile Actions on iOS

This one deserves its own box because iOS behaves differently from Android.

⚡ How it works

Powered by FunctionGemma 270M: it translates a plain-English request into a structured function call, then fires a real OS action. Example commands:

• "Show me the San Francisco airport on map"
• "Create a calendar event for 2:30 PM tomorrow"
• "Turn on the flashlight"

🔒 The iOS sandbox

iOS is sandboxed tighter than Android, so Mobile Actions is limited to public Apple APIs: EventKit (calendar), MapKit (maps), and the flashlight toggle — not general device control. Calendar & notification actions exist but are more limited than on Android.

⚠️ Permissions & benchmarking

  • MCP tool calls ask first. The model requests permission before executing an action, with an "Always allow" option — expect a prompt the first time.
  • Get numbers for YOUR phone. Run the in-app benchmark (Models Management → top-left menu) to see real performance specific to your iPhone 17 before trusting any config.
Quick setup

Get running in 4 steps

  1. Install from the App Store — search "Google AI Edge Gallery" (iOS) or grab it on the Play Store for Android.
  2. Download a default model — start with Gemma 4 E2B or E4B from the in-app model list.
  3. Import extras from Hugging Face — search & import add-on models directly inside the app. No manual sideloading needed anymore.
  4. Benchmark, then tune — run Performance Metrics, pick GPU or CPU, then set per-task configs (see Configure below).

Honest take

Pros & limitations

👍 Pros

  • Fully offline — works with no wifi/signal, in airplane mode.
  • Private by design — prompts, images, audio never leave the device.
  • Free, no accounts, no rate limits, no token metering.
  • Model-swappable sandbox — import anything from Hugging Face.
  • Real agentic tiles (Agent Skills, Mobile Actions) to study tool use.
  • On-device benchmarking to right-size models per phone.

👎 Limitations

  • Small models — weaker reasoning & shorter memory than cloud AI.
  • Knowledge is frozen at training time; no live web.
  • Heavy use drains battery & warms the phone.
  • iOS sandbox limits Mobile Actions to a few public APIs.
  • Setup/tuning has a learning curve (that's what this guide is for).
  • Big models may not fit in memory on-device.

Measure, don't guess

Benchmark — tune to your phone

The benchmark screen (Models Management → ⋮ → Benchmark Model) is the one place you can turn "GPU or CPU? which model?" into a real number. Set the sliders to mimic a task's token shape, run it on GPU, then CPU, and compare. Its four knobs map to actual inference physics:

📥 Prefill tokens

How fast the model reads your input — prompt, context, image/audio tokens, tool schemas. Parallel & compute-heavy, so GPU usually wins. This is your time-to-first-token.

📤 Decode tokens

How fast it writes output, one token at a time. Memory-bandwidth-bound — the streaming speed you actually feel. Long code & transcripts live here.

🔁 Number of runs

Repeats, for a stable median. 3 = quick read, 5 = confident. More runs = more heat & battery, so keep it low for casual checks.

⚙️ Accelerator

The thing you're A/B testing. Run identical settings on GPU then CPU and compare medians — the winner flips with model size and task.

🌡️ The throttle test

Run the same benchmark twice, back-to-back. If run 2 is noticeably slower, your phone is thermally throttling — so long transcriptions and agent loops will degrade over time even when the first burst looks fast. Sustained speed matters more than peak.

⚙️ GPU isn't always the winner

GPU has spin-up overhead that makes it lose on the 270M model and very short chats — which is exactly why the app lets you benchmark E4B on CPU. Never assume; test both.

🧵 32K context is a trap

Gemma 4 E2B supports up to 32K context, but prefilling that many tokens on-device is brutally slow and memory-hungry. Keep contexts lean, and watch peak memory against model size (E4B 3.66 GB · 3n-E2B 3.39 GB · E2B 2.59 GB).

Plain-English

Parameter glossary

🧠 The one thing to remember

Temperature reshapes the probability distribution BEFORE filtering; Top-K / Top-P decide WHICH tokens are eligible AFTER. Temperature changes how flat or peaky the odds are; Top-K/Top-P then trim the list of candidates the model may pick from.

Max Tokens+
The ceiling on how long a single response can be. Higher = room for full code files or long transcripts, but slower and more memory. Lower = snappier, forces brevity. Set it to the longest output you realistically need for that task.
Top-K+
Keep only the K most-likely next tokens, then sample among them. Low K (1–20) = focused, safe, repetitive-leaning. High K (40–64) = more variety and surprise. K=1 is greedy (always the single top token).
Top-P (nucleus)+
Keep the smallest set of tokens whose probabilities add up to P, then sample among them. 0.9 is a solid default; lower tightens focus, higher (0.95–0.99) loosens it. Works alongside Top-K — the stricter of the two wins.
Temperature+
The creativity dial. 0–0.3 = precise, factual, deterministic (code, transcription, function calls). 0.7–0.9 = natural, conversational. ~1.0–1.1 = wild, creative, less predictable — the practical ceiling for small on-device models, which fall apart above it. It stretches or flattens the odds before Top-K/Top-P filter.
Accelerator (CPU / GPU)+
Which chip runs the model. GPU is usually faster for larger models and worth it on the iPhone 17; CPU can be steadier for tiny models and lighter on heat/battery. Benchmark both — the winner depends on the model.
Speculative Decoding+
A speed trick: a small "draft" guesses several tokens ahead and the main model verifies them in one pass, so you get more tokens/sec with identical output. On Gemma 4 it uses native Multi-Token Prediction (MTP) — toggle it with "Support speculative decoding" in config. Free speed for text; leave off for vision/audio where it doesn't apply.
Enable Thinking+
Lets the model reason step-by-step before answering (Gemma 4's Thinking Mode). On for hard reasoning, code, agent planning — better answers, slower. Off for casual chat, transcription, quick actions — faster, less overthinking.

System prompt library

Paste one of these into the model's system-prompt field. Start with the Core template, then add a task-specific append line below it when you switch tiles. To copy: tap and hold inside a code block, then Select All → Copy.

Core template — identity + behavior

You are a fast, private, on-device AI assistant running locally on my iPhone via Google AI Edge Gallery. You have no internet access — never claim to browse, fetch, or look anything up online. Work only from what I give you and what you already know.

BEHAVIOR
- Be direct and concise. Lead with the answer, then the reasoning only if it helps.
- If you are unsure, or a request needs live/online data, say so plainly instead of guessing or inventing sources.
- Match my level: skip filler and don't over-explain the basics unless I ask.
- When I ask for code, return complete, runnable snippets — no placeholders, no "TODO".
- Format with light Markdown (short lists, code fences) when it makes the answer clearer.
- Everything stays on this device, so be candid, specific, and useful.

Lightweight alternative — low-maintenance

You are a concise, private, on-device assistant with no internet access. Answer directly, admit uncertainty, and never invent facts or sources. Keep it short unless I ask for more.

📏 Match the prompt to the model size

Long system prompts eat context and can dilute instruction-following on small models. On E2B (or Gemma 3 1B) the lightweight prompt often behaves better than the full template; save the full Core template for E4B, where there's headroom to actually follow all of it.

Task-specific append lines

Add one of these under the Core template when you switch tasks.

Prompt Lab — code

TASK: Act as a senior engineer. Return only complete, working code plus a one-line explanation. No placeholders, no "TODO". Prefer the standard library, handle the obvious edge cases, and note any assumptions in a short comment.

Prompt Lab — creative

TASK: Prioritize originality, voice, and vivid detail over caution. Take creative risks, vary sentence rhythm, avoid clichés, and give me the piece itself — not a description of it.

Ask Image

TASK: Answer strictly from what's visible in the image. Be specific about what you actually see; if something is ambiguous or cut off, say so. Don't invent text, brands, or details that aren't clearly present.

Audio Scribe — transcription

TASK: Transcribe faithfully — preserve wording and speaker turns; keep fillers only if they carry meaning. Do not summarize or edit unless I ask. For translation, keep the original meaning and tone, and flag anything unclear as [inaudible].

Agent Skills — tool use

TASK: You may call the loaded tools/skills to complete the request. Plan the steps first, then call one tool at a time and wait for each result before the next. Only call a tool when it's actually needed — otherwise just answer. Confirm with me before any irreversible action.

Mobile Actions / Tiny Garden — function call

TASK: Convert my request into exactly one structured function call using the available device actions. Fill every required argument from my message. If a required detail is missing, ask one short question instead of guessing. Do nothing beyond the single requested action.

Cantonese / Mandarin translator — travel

TASK: Be my offline Cantonese/Mandarin travel translator.
- Default target is Cantonese (Hong Kong). If I say "Mandarin", switch.
- For each phrase give three lines: (1) the translation in characters, (2) romanization — Jyutping with tone numbers for Cantonese, Hanyu Pinyin for Mandarin, (3) a short natural back-translation so I can sanity-check the meaning.
- Default to a polite register. Flag anything that would sound rude, too casual, or is easy to mispronounce into a different word.
- If there's no clean local equivalent, say so and give the closest natural phrasing instead of a literal word-for-word.

ℹ️ Not a bug: Agent Skills' default prompt

When no MCP tools are loaded, Agent Skills automatically switches to a built-in "skills only" default system prompt. That's expected behavior — if your custom prompt seems to vanish there, load a tool/skill and it comes back.

Extend the model

Agent Skills — three tiers & what to build

Agent Skills pairs a planner (E2B/E4B, which reasons) with a function-caller (FunctionGemma, which emits the tool call) — that's the "2 models" on the tile. Don't just load an MCP server and hope; think in three tiers. And keep every tool description terse — schemas are re-fed each turn, so they inflate prefill (see the Agent Skills row in Benchmark).

1 Prompt personas

No MCP, zero setup. Reusable system prompts for recurring jobs. Highest ROI — start here today.

2 Local function tools

Deterministic calculators/converters the model calls for things LLMs botch (arithmetic, unit conversion). Offline-safe pure functions.

3 Multi-tile chains

Workflows that hand output between tiles — Audio Scribe → summarize → flashcards, or Ask Image → extract → save.
